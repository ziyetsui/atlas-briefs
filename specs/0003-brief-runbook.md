## 竞品爆款 Brief 制作手册（v1 · 2026-10-15）

从拍吧（pepa）这一份的实际制作过程整理而来。新品牌照着这份走：**写一个配置文件 → 跑引擎 → 看页面 → 发布**。Ancher 是按这份手册做的第一个。

### 0. 产出物

一个单页 brief：我的产品 → 锁定竞品 → 竞品爆款 → 爆款拆解 → 规律与落地。
页面模板只有一份（`template/brief.html`），每个品牌只有数据不同（`site/<slug>/data.js`）。

```
briefs/<slug>.py          ← 你要写的：品牌配置（所有判断都在这里）
scripts/atlas_build.py    ← 引擎：读配置 + 素材库，算出所有能算的
scripts/sync_template.py  ← 把模板复制到每个 site/<slug>/index.html
site/<slug>/data.js       ← 生成物，不要手改
site/briefs.js            ← 首页的 brief 列表
data/library/             ← 素材库导出（items.json + det.json，不进仓库）
data/library-jg/          ← 聚光内容广场直抓的素材库（同格式，带真实阅读 / 点赞 / 粉丝），见 0004
```

> **素材从哪来**：旧素材库（`data/library/`）只覆盖 AI / 全行业。新品类先看库里有没有足够的同类笔记（关键词扫一遍，少于 50 条就算没有），没有就按 `specs/0004-juguang-source.md` 从聚光内容广场抓，引擎加 `--lib data/library-jg`，品牌配置里写 `SOURCE`（来源名 + 数据边界一句话）。

### 0.1 硬性要求：所有视频和图文都能在网页内看（2026-10-15 加）

- 页面上出现的每一条笔记（形式例子、拆解主例、同形式的其他例子、规律例子）都必须**在网页里看完**，不跳到小红书：
  - **视频笔记**：点封面直接弹出播放器播放（已有：`video.src` + `poster`，弹窗按视频比例自适应，Esc 关闭）。
  - **图文笔记**：点封面弹出图集，能左右翻看全部图片，下面显示正文（待做：需要 `images[]` + 正文全文，弹窗沿用视频播放器的样式和交互）。
- 「看原文 ↗」保留，只作补充入口。
- 数据要求：每条笔记带齐素材，托管在和封面同一个 R2 bucket：
  - 视频：`video: {src, poster, durationSec}`
  - 图文：`images: [{src, w, h}]` + `body`（正文全文）
- 选例子时，同等条件下优先选素材已经齐全的笔记。
- 发布前逐条点开所有例子，确认能播、能翻。
- **现状（2026-10-15 补抓后）**：两份 brief 共 56 条笔记，**44 条能在网页内看**（拍吧 22 / 28：视频 12 / 15、图文 10 / 13；Ancher 22 / 28：视频 16 / 17、图文 6 / 11）。补抓的笔记同时带上了正文和真实的点赞、收藏、评论数。剩下 12 条找不到签名链接（多半已删除、设为私密或作者主页不公开），保留「看原文」；其中包括两条拆解主例（拍吧「炸鱼」、Ancher「旅行」）。
- **补齐路径**（`scripts/fetch_xhs.py`，需要 Chrome 装 OpenCLI 扩展并登录小红书）：
  1. 导出清单：`data/fetch/targets.csv / .json`（brief 里用到的全部笔记）。
  2. `python3 scripts/fetch_xhs.py resolve`：小红书只认带 `xsec_token` 的签名链接，素材库里只有裸链接。脚本先按标题搜，搜不到再按作者名找到作者主页，从主页列表里拿签名链接。每次请求间隔 3 秒，约 1–2 分钟一条。
  3. `python3 scripts/fetch_xhs.py download`：下载视频 / 全部图片，同时抓正文和真实的点赞、收藏、评论数。
  4. `python3 scripts/fetch_xhs.py upload`：传到 R2 `atlas-media/atlas/briefs/media/<笔记 ID>/`，写 `data/fetch/media.json`。
  5. `python3 scripts/atlas_build.py <slug>`：引擎把 media.json 合并进笔记（video / images / body / likes …），页面自动出现播放和图集。
  - 找不到签名链接的（笔记已删除、作者主页不公开），在 `signed.json` 里是 `null`，页面保留「看原文」。

### 1. 产品信息（10 分钟）

从官网 / 截图写 `PRODUCT`：名字、一句话、品类、价格、人群、平台、本轮目标、3 个卖点。
- 拿不准的（人群、目标）照写推断，**末尾标「（待确认）」/ 开头写「待确认：」**，页面会如实显示。
- `copy.transferDef`：可迁移度的定义，一句话说清「对这个产品来说，什么叫好抄」。

### 2. 圈候选池（核心判断 ①）

目标：在素材库里找 **抢同一批人、讲同一个故事** 的品牌或赛道，不只是同品类。
素材库里往往没有同类产品（拍吧就没有），这时按「人群 + 承诺」圈，不按「产品形态」圈。

步骤：
1. 关键词扫全库：品牌名、品类词、承诺词（赚钱 / 一键 / 爆款…），**同时匹配标题和账号名**（很多投放笔记标题不写品牌，账号名写）。
2. 每组看 top 笔记的标题，剔除噪音（例：「羊毛衫」不是薅羊毛；「课件 PPT」是卖模板不是 AI 工具）。规则写进 `match`，个别噪音用 id 排除。
3. 一条笔记只属于一组：重叠的用 `exclude`。
4. 每组打三个判断分（0–100）：**人群重合 / 动机重合 / 动作重合**。相关性 = 0.3·人群 + 0.4·动机 + 0.3·动作。
5. 爆品度由引擎算：0.5·榜内百分位中位数 + 0.3·爆款占比（≥ 80）+ 0.2·素材量（40 条封顶）。
6. 分界线（`CUT`）默认 70 / 50。右上角「核心对标」区就是入选；落选的每组写一个 `drop` 标签（动作对不上 / 样本太少 / 动机不对 / 人群不对 / 账号太集中 / 只做单一输出）和一句 `why`。
7. `SELECTION.common` 写入选组的 3 条共性，能用数的用占位符（`{picked_notes}` `{picked_accts}`）。

> 经验：8–10 组候选、入选 3 组最合适。只有个位数笔记的组再像也别选，放在「内容借鉴」区当参考。

### 3. 拆爆款形式（核心判断 ②）

每个入选竞品拆 **3 种形式**：
1. 把这组所有笔记按百分位排出来，读标题找重复的打法（封面套路、标题句式、人设）。
2. 写成 `fmt` 规则（正则或 id 集合），每种形式一句 `desc`、一个内容标签（利益刺激 / 人设故事 / 实用攻略 / 效果展示 / 跨圈钩子 / 场景种草 / 品牌活动）。
3. 每种挑 3 个例子：**优先百分位高的、素材库里有视频的**（`video` 不为空的笔记网页里能直接播放）。
4. **必须看封面**：把 27 张例子封面拼成 3 张对照图看一遍，再定稿描述。拍吧这一步发现了「到账截图当封面」，光看标题看不出来。
5. 可迁移度底分（`transfer`）：按形式给，引擎加 ±12 的确定性抖动。页面会标「判断分」。
6. 每个竞品写一句 `takeaway`：右上角（爆款 × 好迁移）里的笔记有什么共同点。先跑一次引擎看右上角有哪些，再写。

### 4. 拆解（每个竞品 1 条主例）

主例：该竞品最能代表打法、百分位最高、最好有视频的那条。结构固定：
- **账号**：名字、类型、库里几条、矩阵（同活动多少条 / 多少个号）。
- **流量从哪来**，分两层：
  - 定量 `quant`：素材库只有榜单记录（没有点赞、粉丝、流量来源占比）。`lists: 'auto'` 会自动填主例的全部榜单排名；`summary` 写一句人话，`from` 写数据来源。拿不到就 `null`，页面显示「仅定性」。
  - 定性 `qual`（必填）：判断类型（投放驱动型 / 搜索长尾型 / 人群定向型 / 投放加热型…）+ 一句理由；关键词表写每个词出现在 **标题 / 封面 / 正文 / 话题** 的哪里、起什么作用；3 个推测的长尾搜索词。
- **怎么变现**：步骤链，没有数字就不写数字；推断的标「（推断）」。
- **内容怎么搭**：封面 / 标题 / 正文 / 视频逐项；没看到实物的放进 `inferred`，页面标「推断」。
- **为什么有效**：3 条。

### 5. 规律（3 条）

1. 先在全部竞品笔记上试 5–6 个候选特征（正则匹配标题），算「有 / 没有」的爆款率。
2. 选差距最大、最能落到产品上的 3 条。**反直觉的也要**（Ancher：喊「爆款 / 神器」的反而更低）。
3. 证据由引擎算：`{'rx': ...}` 算有 / 没有的爆款率；`{'campaigns': [...]}` 算矩阵规模。`claim` 里用 `{withHit}` `{withoutHit}` 占位，数字永远和数据一致。
4. 每条配 3 个例子 + 落地：`apply`（标题、封面、脚本、建议看的指标）+ `mock`（示意封面文字）。

### 6. 生成、检查、发布

```sh
python3 scripts/atlas_build.py <slug>       # 打印候选池、各形式、右上角、规律，先看数对不对
python3 scripts/sync_template.py             # 模板 → site/<slug>/index.html
```
- 在 `site/briefs.js` 加一行。
- 检查：浅色 / 深色 / 390 宽各截一次全页；控制台无报错；四象限标签不重叠；逐条点开所有例子，视频能播、图文能翻（见 0.1）。
- 发布：推到 GitHub，Actions 把 `site/` 部署到 Pages。

### 7. 数据边界（每份 brief 都要在页面上说清）

- 素材库 = 小红书聚光 / 蒲公英 / 热门榜单记录：有榜内百分位、排名、投放目标，**没有点赞数、粉丝数、流量来源占比**。
- 发布日期由笔记 ID 前 8 位（十六进制时间戳）推算。
- 相关性、可迁移度是判断分；爆品度、爆款率、规律证据是算出来的。
- 爆款 = 榜内百分位 ≥ 80。

### 8. 三份实例

| | 拍吧（pepa） | Ancher | 橘子肉肉（juzi） |
|---|---|---|---|
| 素材来源 | 旧素材库 | 旧素材库 | 聚光内容广场直抓（0004），137 个榜单 → 5,848 条 |
| 竞品圈法 | 素材库没有同类 → 按「用手机赚钱」的人群 + 承诺圈 | 按「创作者 + 一处搞定 / 一键成品」圈 | 直接同类（橘子干）还不够火 → 按「解馋时刻」+ 同货架酸甜果干 + 新式果脯圈 |
| 候选 / 入选 | 8 组 / 3 组 | 9 组 / 3 组 | 10 组 / 3 组 |
| 入选 | 副业接单赛道、京东 · 夺金密令、超自然行动组 | AI 自媒体爆款工作流、AI 一键成品（PPT / 网页）、千问 | 嘴馋解馋零食、酸甜果干、喜茶 · 芭乐果脯 |
| 3 条规律 | 把钱写在第一眼 / 一个活动几十个素人号 / 先点名人群 | 说「一个地方全搞定」 / 给时间承诺 / 别喊爆款，直接给成品 | 把零食放进一个时刻 / 先点名一类人 / 产地别放标题第一位 |

> 橘子肉肉这份的新做法：新增「还不够火」落选标签（相关性很高但爆品度 < 50 的直接同类，作为空位写进结论）；四象限横纵轴会按数据自动放宽到 100。
